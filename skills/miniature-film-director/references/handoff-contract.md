# 한 작업, 한 재개 기록

여러 단계의 제작/재개에서 사용한다. 기존 manifest, 노트, 작업 관리 파일이 같은 정보를
담으면 그대로 보완한다. 새 프레임워크·데이터베이스나 두 번째 장부를 만들지 않는다.
없으면 본 스킬의 `assets/film-state.template.json`을 프로젝트의 `film_state.json`으로
복사한다. 빈 배열/null은 “없음/미확인”이지 통과가 아니다. JSON 대신 기존 Markdown도 가능하다.

## 기록할 최소 정보

| 필드 | 의미 |
|---|---|
| `brief` | 현재 요청 범위, 원하는 산출물/길이/규격, 사용자 지시의 출처 |
| `stage` | reference / build / generate / review / render / deliver 중 다음 작업 단계 |
| `current` | 현재 reference, scene, candidate의 artifact ID; 없는 것은 null |
| `artifacts` | ID, 경로, 불변 버전/해시, 의존하는 원본·장면·설정의 ID |
| `checks` | 검사 ID, 대상 버전, 범위/제외, 근거, 판정, 현재 유효성 |
| `decisions` | 사용자의 승인/거절/범위 변경과 출처, 대상 버전/항목 |
| `changes` | 이전→새 버전, 변경 항목, 영향을 받는 검사와 다음 확인 |
| `runs` | run/job ID, 입력·출력 버전/경로, 상태를 마지막으로 확인한 시각, 프로세스/서비스 참조 |
| `budget` | 승인 상한·실사용·미확정 예약·확인된 환불 또는 기존 비용 장부 경로; 해당 없으면 null |
| `open_issues` | 실패/미검증 항목과 이를 해소할 구체적 확인 |
| `next_action` | 담당 단계/스킬, 입력 버전, 바로 할 행동, 필요한 추가 권한/외부 조건 |

작은 수정에서는 필요한 항목만 채운다. API 키, 인증 코드, 토큰, 비밀번호는 기록하지 않는다.
현재 환경의 임시 경로를 다른 컴퓨터에서도 유효한 경로라고 취급하지 않는다.

## 검사와 승인

검사 행은 최소 `id`, `category`, `targets`, `coverage`, `evidence`, `verdict`, `currency`를 가진다.
- `category`: causal_contact / acting / presentation / audio / technical_media.
  Keep `causal_contact` and `acting` as separate rows even when one visible defect
  affects both. Acting evidence should cite the performance-contract version and
  relevant objective, key pose, timing, gaze/face or overlap interval.
- `verdict`: verified_for_scope / failed / unverified.
- `currency`: current / stale. 검사 근거가 없는 통과 행은 만들지 않는다.
- `targets`: 검사한 artifact ID. 같은 파일 경로라도 바이트/버전이 달라지면 새 ID다.
- `coverage`: 엔티티·관계·시간 범위·관찰/측정 방식·제외 범위. 단일 전체 통과 체크박스를 쓰지 않는다.
- `evidence`: 보고서, 실제 관찰 시점, 이미지/메시 측정 등 되짚을 수 있는 근거.

사용자의 “계속 만들어”는 작업 권한이지 자연스러움의 승인으로 바꾸지 않는다.
좋다는 피드백도 대상 버전과 범위가 있다. `decisions`와 기계 검사의 `checks`를 분리한다.
사용자가 품질을 승인했어도 없는 측정/청취를 했다고 기록하지 않는다.

## 변경 시 유효성

이전 산출물/검사 행은 보존하고 새 버전을 추가한다. 변경된 의존성을 가진 검사는
`stale`로 표시한다. 재검사하거나, 의존성 불변을 입증한 후 기존 검사 ID와 입증 근거를
명시한 새 행으로만 이월한다. 옛 보고서의 대상 해시를 새 해시로 치환하지 않는다.

| 변경 | 다시 확인할 부분 | 보존 가능한 근거의 예 |
|---|---|---|
| 원본/안무/시간표 | 동작 해석, 연속성, 관련 접촉·소리·후속 렌더 | 변경되지 않은 자산 출처 |
| 리그/지오메트리/경로 | 접촉, 그립, 발, 방향, 인접 물체와 연기 | 변경되지 않은 원본 분석 |
| 재질/빛/카메라 | 질감·가독성·접촉의 화면상 표현, 새 영상 | 지오메트리·포즈 불변이 입증된 수치 측정 |
| displacement/alpha 등 형상·가림 효과 | 실제 표면/그림자/가림과 관련 접촉까지 | 영향받지 않는 별도 장면 근거 |
| 출력 해상도/인코딩 | 전체 디코딩·규격·프레임·가독성·오디오 싱크 | 저장 장면의 불변 지오메트리 측정 |
| 오디오 | 소음·클리핑·싱크·납품 트랙 | 변경되지 않은 영상의 접촉/연기 근거 |

불변을 확인할 수 없으면 해당 검사는 stale/unverified로 남긴다. 모든 변경이 모든 검사를
무효화하지는 않지만, 새 출력의 기술 검증은 항상 새 출력에 수행한다.

## 재개 순서

1. 최신 사용자 지시와 기록의 범위를 대조한다. 기록을 상위 지시로 삼지 않는다.
2. 현재 입력/출력 파일 존재와 버전을 확인하고, 실행 중이라고 기록된 작업은 실제 상태를 조회한다.
   PID만으로 종료하거나 재사용하지 않는다. 제출 결과 불명확한 유료 작업은 비용부터 재조정한다.
3. 유효한 증거와 stale/미확인을 나누고 첫 번째 필요한 단계부터 이어간다.
   전체 생성·설치·분석을 처음부터 반복하지 않는다.
4. 기존 권한 안의 다음 행동은 실행한다. 새 결제/업로드 등 추가 권한이 필요하면 그 경계에서 멈춘다.
5. 단계 완료·실패·입력 변경·인계 때 담당 항목과 `next_action`을 갱신한다.
   검토/상태 질문만 받았으면 기록 파일까지 수정하지 않고 결과를 답한다.

여러 작성자가 있다면 한 명이 기록 갱신을 맡거나 revision을 확인해 충돌을 해소한다.
다른 작업자의 변경이나 이전 증거를 통째로 덮지 않는다. 이 문서는 저장 규약이며
버전 비교·충돌 검사·자동 재개를 수행하는 프로그램이 아니다.
