# 협의형 제작 루프

이 테이블 시리즈에서 사용자가 지정한 기본 순서다. 최신 요청이 우선하며, 상태 확인이나
조사만 하는 턴을 제작으로 확대하지 않는다. 반복 횟수보다 합의된 결과가 중요하다.

## 1. 러프안 → 질문하며 기획 고도화

- 먼저 현재 아이디어를 짧게 재구성하고, 성립하지 않는 인과관계·시간·시점·물체 출처를 찾는다.
- 결과를 바꿀 핵심 질문을 대화 가능한 분량으로 묻는다. 이미 답한 정보를 다시 묻거나
  도구/API 용어를 사용자에게 결정하게 하지 않는다. 대안과 추천 이유를 함께 제시한다.
- 목적, 사건 순서, 주요 엔티티, 원인/결과, 길이, 투사/광고 구분, 카메라, 필수 자산이
  합리적으로 연결되고 중요한 미결정이 해소되면 에이전트가 기획 준비 완료를 판단한다.
- 준비 완료는 최종 제작 승인이 아니다. 판단 근거와 남은 가정을 짧게 밝히고 콘티로 진행한다.
  단순 선택은 합리적으로 제안하되, 중요한 사용자 의도를 임의로 바꾸지 않는다.

## 2. 이미지 콘티

- 씬/컷 ID, 초/프레임, 액션, 시작/끝 상태, 촬영·편집·효과·빛·소리를 작성한다.
- ChatGPT의 이미지 생성 도구로 필요한 키프레임과 전환의 전/가림/공개/후를 그린다.
  생성 이미지를 직접 검사한다. 좋은 프롬프트만으로 그림이 규칙을 지켰다고 하지 않는다.
- 전체 화면 wipe는 모든 모서리까지 덮는다. 고정 카메라와 장면 컷은 다른 개념이다.
- 그림·문서·타이밍 불일치를 명시하며 장면에 중요한 미결정은 사용자와 다시 해결한다.

## 3. 전체 단순 메시 프리비즈

- 상세 모델링 없이 Blender의 기본 도형으로 **모든 구간**을 움직여 본다. 콘티 스틸의
  슬라이드쇼를 3D 프리비즈라고 부르지 않는다. 실제 출입, 방향, 도구/재료 이동, 전환을 구현한다.
- [대조 지침](../../animation-causal-staging/references/storyboard-previs.md)에 따라 같은 시간의
  콘티와 영상을 나란히 보여준다. .blend와 영상, 컷/시간 연결을 보존한다.
- 공간/시간 문제가 드러나면 고비용 제작 전에 콘티로 되돌아가 수정한다. 프록시 수준에서
  검사하지 않은 손가락·얼굴·관절·시뮬레이션·최종 재질을 완성했다고 하지 않는다.

## 4. 사용자의 최종 컨펌

사용자가 볼 수 있는 대조본을 제시하고 **콘티 버전 + 프리비즈 버전 + 남은 제한**을 묶어
컨펌받는다. “어, 진행”이 질문 답변인지, 프리비즈 제작 허가인지, 본편 최종 컨펌인지 문맥을 확인한다.
이미지 열람, 기술 검사, 에이전트의 준비 완료, 이전 시도의 승인으로 이 관문을 통과하지 않는다.

이후 이야기·구도·핵심 동작·전환·입력이 실질적으로 바뀌면 영향을 받는 컨펌을 재확인한다.
철자 정정처럼 결과를 바꾸지 않는 수정까지 기획 전체 재승인을 강제하지 않는다.

## 5. Higgsfield 제작

- 승인한 프리비즈, 캐릭터/미술 이미지, 컷별 지시를 버전으로 묶고 지원 모델/입력/가격을 확인한다.
- **창작 컨펌과 지출 권한은 별개**다. 입력·계정·상한·시도 범위에 맞는 현재 승인 없이 제출하지 않는다.
- 원형 정렬, 고정 텍스트, 원본 GIF, 정확한 마스크는 필요하면 로컬 후반으로 유지한다.
  생성 결과가 가이드대로 나올 것이라고 보장하지 않는다.
- 제출·회수·비용은 기존 안전 실행기와 장부를 사용한다. 새 승인 시스템을 중복 만들지 않는다.

## 6. 실제 결과 → 납품 또는 대화로 복귀

- 결과를 콘티/프리비즈와 비교하고 기술 파일, 물리/인과, 연기, 미술, 오디오를 나누어 판정한다.
- 의도 불일치면 해당 타임코드와 실제 증거를 보여주고 원인을 구분한다:
  **기획 문제 / 가이드 불명확 / 모델 표현 한계 / 로컬 후반 결함 / 서비스 오류**.
- 기획/모델 문제가 핵심이면 사용자와 다시 논의한다. 대안은 예를 들어 동작 단순화,
  구간 분리, 출처가 보이는 소품 배치, 결정적 합성으로 전환 처리다. 몰래 컨셉을 바꾸지 않는다.
- 확정된 기획 수정은 해당 콘티→프리비즈→컨펌을 다시 거친다. 승인된 범위 내의 단순
  인코딩 수정은 기획 단계로 되돌리지 않는다.
- 실패했다고 자동으로 크레딧을 더 쓰거나 새 작업을 생성하지 않는다. 제출 여부가 불명확하면
  기존 작업/청구부터 확인한다. 기술 완료를 품질 승인으로 바꾸지 않는다.

## 기존 기록에 남기는 상태

기존 `film_state.json`의 `artifacts`, `decisions`, `checks`, `changes`, `runs`, `next_action`을
재사용한다. 상위 `stage`는 기존 규약을 유지하고, 필요하면 `collaboration_phase`로
`brief_dialogue / storyboard / mesh_previs / awaiting_final_confirmation / generation /
candidate_review / revision_dialogue / delivered`를 기록한다. 이것은 스킬의 운영 기록이며
공통 CLI가 자동으로 전부 실행하거나 사용자 발언의 의미를 판정한다는 뜻이 아니다.

컨펌 기록에는 실제 메시지 근거와 대상 버전/해시를 연결한다. 반복 기록에는 무엇이 실패했고
어느 단계까지 되돌아가는지 남긴다. 승인받지 않은 다른 자료·비용·범위로 승인을 이월하지 않는다.
