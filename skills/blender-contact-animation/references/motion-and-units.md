# 모델 생성·리타깃·연속 동작

이 기록은 이 프로젝트에서 관찰한 실패에서 나온 진단 순서다. 특정 체크포인트의
수치와 GPU 문제를 모든 버전의 고정 제약으로 복사하지 않는다. 현재 로컬 코드와 설정을 확인한다.

Kimodo의 지원 기능·Blender 역할 분담은 [kimodo-capabilities.md](kimodo-capabilities.md),
멈춤/연결 진단과 continuation·in-between 설계는 [kimodo-continuity.md](kimodo-continuity.md)를 읽는다.

## 생성 전 계약

- 체크포인트 FPS, 실제 생성 프레임 수, 프롬프트 dispatch, 전환 프레임 규약을 읽는다.
  과거 SOMA 체크포인트는 30fps였고 `multi_prompt=True`가 필요했다.
  리스트를 줬다는 이유만으로 연속 세그먼트 경로에 진입했다고 가정하지 않는다.
- 길이는 결과의 실제 프레임 수로 판정한다. 972/30=32.4초는 30초가 아니다.
  seam 손실을 가정해 세그먼트 길이를 미리 늘리지 말고 짧은 테스트로 확인한다.
- 첫 포즈/끝 포즈, continuation, in-between, 접촉/루트 경로 제약 지원을 현재 API에서 조사한다.
  지원하는 조건 생성으로 이전 클립의 끝 상태를 이어받는 방법을 우선 시험한다.
  독립 클립을 생성한 뒤 회전만 보간하는 것과 조건 생성은 다르다.
- 클립 끝의 위치·회전·속도·지지 발·그립 상태를 다음 클립의 시작 계약에 전달한다.
  이 모두가 Kimodo의 직접 입력 필드인 것은 아니다. 포즈 이력/말단 제약으로 전달할 것과
  Blender에서 유지할 소품·지지 상태를 구분한다.
  겹침 구간의 접촉이 충돌하면 무조건 블렌딩하지 말고 전이 동작을 생성/작성한다.
- 춤/음악 프레이즈와 의도적인 피벗·슬라이드는
  [natural-motion-and-dance.md](natural-motion-and-dance.md)에 따라 별도 다룬다.
  연결 기능이 있다는 것과 실제 후보의 지지·회전·박자가 자연스럽게 이어진다는 것은 다르다.

## Kimodo에서 확인할 것

- Root2D 경로는 모델 좌표의 첫 위치를 기준으로 한다. 미니어처 월드 좌표를 그대로
  넣으면 사람 공간에서 수십 미터 오프셋이 될 수 있다. 상대 원점과 단위를 명시한다.
- 제약 텐서의 device/dtype을 모델과 맞춘다. heading/CFG가 자세를 망치면 짧은
  동일 시드 비교로 분리 진단한다. 과거의 특정 CFG=1.5를 보편 최적값으로 취급하지 않는다.
- 정지 작업에는 불필요한 이동 제약을 걸지 않는다. 총 거리만 아닌 평균 속도/행동을 본다.
- 장거리 경로에서 관절의 절대 원점 거리를 이상 자세로 판정하지 않는다.
  루트 상대 신체 길이, 머리-발 높이, 유한 값, 변속/접촉 상태를 확인한다.
- 과거 MPS 긴 multi-prompt에서 붕괴하고 CPU에서 정상인 사례가 있었다.
  길이를 늘리며 비교하고 현재 결과로 CPU/CUDA/분할 경로를 선택한다. “900프레임 고정 한계”로 단정하지 않는다.
- 시작 로딩과 추론 속도를 분리 측정한다. 모델/텍스트 인코더 누락을 숨긴 폴백이면
  원래 모델로 생성했다고 말하지 않는다. 캐시/토큰 상태를 보되 비밀값을 로그에 출력하지 않는다.

## 단위와 리깅

1. 파일의 루트 이동 단위, rest pose, bone roll, 전방/업 축을 측정한다.
   과거 BVH는 cm, Blender 장면은 m였다. 파일 확장자만으로 단위를 확정하지 않는다.
2. 정지 T-pose, 팔 한쪽 올리기, 정면 한 걸음으로 축·본 매핑을 검사한다.
   원본 rest 모양만 보고 전체 회전을 뒤집지 않는다. 실제 joint 위치와 rest/pose 행렬을 비교한다.
3. twist/helper 뼈와 필수 관절을 구분한다. 무조건 부모 회전을 복사하면 이중 비틀림이 생긴다.
4. yaw 보정은 루트 주위의 자세에 적용한다. 월드 원점 중심으로 전체 경로까지 돌린 뒤
   바뀐 경로를 다시 쫓아 보정하는 피드백을 만들지 않는다.
   보행용 전방 보정을 춤·피벗·의도적 옆걸음에 일괄 적용하지 않는다.
5. FBX preset 루프는 루트 누적 이동을 보존하고 끝-처음 순간이동을 제거한다.
   object transform 곡선이 scale/placement를 다시 덮는지 확인한다.
6. auto-rig 성공 응답은 정상 리그의 증명이 아니다. 뒤집힌 어머니 캐릭터처럼 잘못된
   소스는 별도 수리/교체 대상으로 밝힌다. 원치 않는 배우를 조용히 삭제해 성공으로 만들지 않는다.

발 접지 후 수치만 개선됐다고 하지 말고 원래 동작과 전체 연기를 다시 비교한다.
발 미끄러짐 측정이 실제로 악화되면 그 후처리 후보는 개선으로 승인하지 않는다.
