# A reference-grounded style contract

The upstream library supplies useful craft patterns, not current provider facts.
Apply this local interpretation before reading its conditional references.

## Observe before naming a style

Inspect the actual target image or frames. Separate visible evidence, uncertain
inference and a proposed design. Do not invent a lens, shader, light rig, species
or exact material roughness from a photograph. A captured projection contains
camera/exposure/compression artifacts that may not belong in the render itself.

Use Style DNA in a few lines, with only the axes that matter:

- Core look: what kind of object/world the image should feel like.
- Material language: silhouette, cloth/skin/ceramic/metal/water differences.
- Structural rule: how forms, scale and layers relate, not a decorative overlay.
- Color/light: palette, exposure, source direction, highlight/shadow behavior.

Add a short reject checklist for this brief. For our miniature film it may flag
giant plush proportions, identical glossy material on every surface, a gap around
the plate, unreadable tiny hands, and blanket blur used to fake softness. Match
the actual approved reference; these examples do not override a new user choice.

"Looks AI" does not imply "make photographic." De-slop's grain, skin pores,
compression, imperfect capture and lower quality settings are **not** universal
cures. Preserve high-resolution stylized CG, restrained texture scale, clean
silhouettes and readable contact when that is the target. Do not inject random
scratches/noise merely to satisfy an imperfection quota.

## Bind and preserve

Assign every image a role: actor identity, prop shape, material, layout or light.
Name what not to inherit. For a repeated character preserve scale, silhouette,
outfit and distinctive features across states; a sheet alone proves no rigging.
An image described as "3D" is still an image, not a mesh or Blender scene.

For edits, name what changes and what remains. The exact wording format is
flexible: vision-decomposer's comma-only output is not mandatory for other tools.
Do not infer exact optics or emotion as measured facts. Prefer a few discriminating
observations over camera-brand and adjective lists. Preserve user prohibitions
even if surrounding language is positive.

## Execute and compare

For cinematic look development, read [projection-look-gate.md](projection-look-gate.md).
Keep a contact/debug frame separate from an appearance target. Approve the look in
the actual registered camera and at delivery scale before a costly full render or
generative restyle. Internal acceptance is not user approval; record who reviewed
which frame and what remains unverified. Local short tests can continue within the
existing production request without forcing an extra approval conversation.

Use only supported fields of the available image-generation tool. Model names,
prices and parameter tables in models/gpt-image/nano-banana are unverified pinned
claims; they cannot override the tool's schema. Do not change accounts/providers
or add paid services without authority. Actual image requests use the generation
tool, not just the upstream prompt-only output convention.

Compare the result against the same viewed reference, composition and display
size. Name the failed variable and make a bounded correction within the user's
request; do not launch endless paid re-rolls. A rejected style does not erase good
geometry or authorize changing the story. Candidate motion needs separate review.
