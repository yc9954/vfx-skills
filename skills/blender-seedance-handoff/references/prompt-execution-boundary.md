# 연출 프롬프트와 실행 설정을 분리하기

1. `projection_master`, `cinematic_footage`, `look_motion_pilot`을 구분한다.
   테이블용 콘텐츠에 광고 촬영의 클로즈업/돌리/렌즈 전환을 몰래 추가하지 않는다.
   비트의 변화, 사분면의 변화, 실제 카메라 컷은 서로 다른 지시다.
2. 전문용어는 **대상 + 관찰 가능한 변화 + 시점/방향 + 유지 조건**과 함께 쓴다.
   예: “contact shadow가 받침 접촉점에 붙고, 넓은 그림자는 손님 반대쪽으로 간다.”
   “PBR, cinematic, FLIP”만 나열했다고 물리나 화질이 검증되지는 않는다.
3. 설치된 `visual-video`가 있으면 `cinematic-cg-prompting.md`와
   `higgsfield-prompting-evidence.md`를 해당 스킬의 references에서 읽는다.
   촬영/편집/재질/CG 용어와 출처는 그곳에서 관리하고 여기 중복 사전을 만들지 않는다.
   없으면 같은 구조의 도구 중립 브리프를 만들고 지원 기능을 미확인으로 남긴다.
4. 출력은 연출문, 실제 설정, 로컬 후처리 지시의 세 부분으로 나눈다.
   Cinema Studio의 렌즈 ID와 일반 Seedance의 자유 텍스트는 같은 기능이 아니다.
   mode/입력/길이/해상도/audio/extension은 현재 help/schema로 다시 확인한다.
   블로그의 표기나 예시 플래그를 API 스키마로 복사하지 않는다.
5. 가이드에 줄 자유도를 먼저 정한다. 이미지-only, sparse blockout, motion guide,
   video-edit 중 목적에 맞게 고른다. 잘못된 접촉을 포함한 스켈레톤은 좋은 가이드가 아니다.
   한 입력에 카메라/동작만 맡겼다면 회색 재질이나 진단용 사선 뷰를 최종 기준으로 삼지 않는다.
6. 정확한 접시 테두리·원·문자·4인 배치·광학 보정은 Blender/합성으로 분리한다.
   생성 단위도 한 자리/중앙 무대/테이블 전체 중 하나로 명시한다. 로컬에서 네 자리를
   복제할 계획이면 모델에 네 자리를 동시에 만들라고 하지 않는다. 로컬 소유의 부채
   wipe나 원 이펙트를 생성 프롬프트에도 중복 요청하지 않는다. 모델은 전환 직전의
   안정된 상태까지 만들고, 효과의 주체는 한 곳으로 정한다.
   RGB 생성물에서 실제 alpha, depth, shadow pass, Cryptomatte가 나왔다고 주장하지 않는다.
   후처리 마스크/추적도 경계와 가림을 실제 검수해야 한다.
7. Extension은 끝 프레임 외에 속도, 그립, 지지, 광원/색 기준을 이어받아야 한다.
   반환 영상이 원본 포함인지 추가분만인지 확인해 중복/누락을 막는다. 디졸브로
   두 손이나 두 접시가 겹치면 개선이 아니다. 고정 색 기준으로 연결을 검사한다.
8. 프롬프트 개선/리서치 요청은 유료 실행 승인이 아니다. 현재 도구의 로컬 파일
   경로는 create 시 자동 업로드될 수 있다. 비용·업로드·정책 경계를 그대로 지킨다.
   예산 안의 A/B 테스트를 명시적으로 요청받았을 때만 실제 생성 비교를 진행한다.
