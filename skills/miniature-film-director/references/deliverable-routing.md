# 산출물 우선 라우팅

## 시작할 때 다섯 가지만 복원

`원하는 산출물 | 선택한 backend | 현재 단계 | 재사용할 입력 버전 | 바로 다음 행동`

- backend는 `blender`, `higgsfield`, `hybrid` 중 현재 사용자 선택을 따른다.
- Higgsfield를 요청했을 때 Blender만으로 완료하거나, 이미 있는 가이드를 계속 새로 깎지 않는다.
- 도구 테스트 요청과 실제 제작 요청은 다르다. 연결이 확인되면 원래 요청으로 돌아간다.
- 스킬 이름에 Blender가 있더라도 `blender-seedance-handoff`는 직접 Higgsfield 생성도 담당한다.
  모델이 받지 않는 가이드는 강제로 만들거나 제출하지 않는다.
- 새 pilot이 필요한 구체적 미해결 위험을 한 문장으로 설명할 수 없으면 반복 pilot을 만들지 않는다.
  승인된 본편 범위 안의 실행은 불필요하게 재승인을 반복하지 않지만, 만료/소진된 유료 승인을 재사용하지 않는다.

## 의존성에 따라 재사용

프롬프트 변경은 프롬프트/생성본에, 그립 변경은 가이드/해당 생성본에 영향을 준다.
인코딩만 바뀌면 모션을 다시 생성하지 않는다. 같은 이름이 아니라 실제 파일 해시/버전을 비교한다.
기존 `film_state.json`이 있으면 두 번째 프로젝트 장부를 만들지 않는다.
개별 실행의 quote/request/attempt 영수증은 그 장부의 `runs`에서 참조한다.

## 실행과 검수 분리

견적 → 실제 사용자 승인 확인 → 불변 입력 검증 → 1회 제출 → 상태 조회 → 출력 회수 → 품질/기술 검수.
요청 해시·상한·계정이 다른 승인은 무효다. 응답이 끊긴 제출은 `uncertain`으로 남기고 자동 재시도하지 않는다.
새 파일/새 run 이름으로 같은 미확정 요청의 중복 과금을 우회하지 않는다.
견적·설치 검사·상태 조회가 유료 생성이나 새 업로드를 발생시키면 안 된다.

## 경로와 기록

재사용 실행기는 저장소 위치를 기준으로 경로를 찾는다. 사용자 홈 절대경로, CWD,
폴더명에 공백이 없다는 가정에 의존하지 않는다. 외부 도구는 argument 배열로 실행한다.
과거 보고서/입력 해시는 경로 정리 때문에 덮어쓰지 않는다. 이전 경로→현재 경로 매핑을 별도로 둔다.
`.blend` 등 내부 참조는 텍스트 치환 대상이 아니다. 실제 로드 검증 전에는 이관 완료로 단정하지 않는다.

기술 완료, 연기/접촉 검수, 사용자 승인은 별개다. 파일이 생겨도 자연스러움이 보증되지는 않는다.
