# Kimodo 연결: 멈춤을 만들지 않는 설계와 진단

지원 기능은 [kimodo-capabilities.md](kimodo-capabilities.md), 춤의 지지/박자 규칙은
[natural-motion-and-dance.md](natural-motion-and-dance.md). 아래의 원인 후보를 확인 순서로
사용하고, 특정 영상의 원인을 보지 않은 채 전부 확정하지 않는다.

## 먼저 어느 단계에서 생겼는지 분리

1. **요청/경로**: prompt에 stop/settle/begin이 반복되는가? 경유점마다 ease-in/out으로
   속도가 0이 되는가? 이동 거리·시간·보행 스타일이 모순되는가? 실제 대기 구간은 무엇인가?
2. **생성 원본**: 올바른 multi-prompt인가? 이전 자세 이력과 다음 행동이 맞는가?
   다음 구간이 너무 짧아 전이만 하다 끝나는가? 양손/지지 발이 서로 모순되는가?
3. **후처리**: root 경로만 축소·재배치했는가? yaw만 돌려 planted 발을 이동시켰는가?
   모든 접촉을 고정해 춤/점프를 지웠는가? 파생 채널은 원본 좌표에 남았는가?
4. **Blender**: retarget 축·스케일·FPS, NLA strip 간 빈 구간/hold/extrapolation,
   자동 ease/시간 재매핑, object transform과 bone root 이중 이동을 실제 파일에서 확인한다.
   이 중 하나가 있었다고 코드 확인 없이 단정하지 않는다.

원본이 자연스럽고 이후에만 깨지면 생성 모델을 다시 돌리는 것이 첫 수리가 아니다.
저장 배열의 유한 값/평균 신장이 정상이라는 기존 검사는 붕괴 검사일 뿐 연속성 검사가 아니다.

## 2026-09-21 로컬에서 확인한 강한 증거

`pipeline/journey.py::plan_journey`는 각 travel leg에 `t*t*(3-2*t)`를 독립 적용한다.
양 끝 미분이 0이고 인접 leg의 endpoint를 중복 포함한다. **단순 경유점도 정지 지점**이 된다.
실제 baker 경로의 travel→travel 경계(4.9, 8.0, 19.8초)에서 재구성한 목표 속도는 0이었다.
저장 모션의 19.8초 주변 ±8프레임 smoothed-root 속도 중앙값은 약 0.144m/s였다
(해당 travel의 명목 평균은 0.85m/s). 생성 결과가 목표를 완벽하게 따라야만 문제가 생기는 것은 아니다.

`pipeline/generate_dance.py::recentre`는 root 경로만 수축하고 프레임별 offset을 전신에 더한다.
시간에 따라 다른 offset은 world-space planted foot를 보존하지 않는다. 고정 발 합성 예제에서
root 이동을 20%로 줄였더니 정지 발이 0.8m/s로 움직이는 반례를 실제 함수로 확인했다.
이 수치는 기존 영상의 실측 slip 수치가 아니다. 몸+경로+장면의 일관된 단위 축소와 구별한다.

저장된 DANCE30/JUMP30은 각각 1020프레임=34초인데 segment 명세는 30초다.
명목 duration만으로 seam 프레임을 추정하지 않는다. dance 기록에는 감속·정지 프롬프트가
있고 footlock 보고값도 0.01983→0.02114m/s로 악화됐다. before 원본을 재생성해 검증한 것은 아니다.
코드/배열/메타데이터 증거는 프로젝트의
`skill-maintenance/kimodo-capabilities-20260921.kojqdB/audit.json`에 버전 해시와 함께 있다.

## 연속 이동: 경유점과 목적지를 구분

- 이동 공간의 곡선과 시간에 따른 진행 속도를 분리한다. 같은 보행은 여러 목적 점을 지나도
  하나의 속도 프로파일로 이어간다. 실제 정지/집기/회전 준비에만 감속·대기를 배정한다.
- 곡선의 매개변수를 선형으로 늘리는 것만으로 일정한 실제 속도가 되지는 않는다.
  호 길이 기반 시간화와 연속 접선/속도를 확인한다. 급격한 코너는 도는 반경·시간이 필요하다.
- 장애물 우회로가 길어지면 원래 시간을 유지한 채 달리게 만들지 말고, 시간/속도를 다시 조율한다.
- root 2D만으로 전신 충돌을 해결했다고 하지 않는다. 몸/옷/든 물건의 여유와 다른 배우도 확인한다.
- 미니어처는 사람 공간에서 동작·환경을 일관되게 환산한다. 나중에 root만 접시 안으로
  클램프하지 않는다. 필요한 범위 안에서 다시 생성하거나 접촉을 보존하는 전신 수정이 필요하다.

## multi-prompt가 실제로 하는 일

검토한 `_multiprompt`는 이전 결과 끝 K프레임의 full-body 위치와 손/발 말단 조건을
다음 생성 앞에 붙인다. 새 동작 N프레임은 N+K 길이로 생성하며, 기존 tail K를 교체한다.
후처리 OFF 경로는 두 tail을 feature 공간에서 선형 blend, ON 경로는 구간별 보정/재인코딩한다.
따라서 정상 입력에서 최종 길이는 **sum(segment_frames)**다. seam 손실을 예상해 미리 늘리지 않는다.
실제 배열 길이도 별도 검사한다.

K는 **강제로 멈추는 프레임 수가 아니다**. 길수록 무조건 매끄럽지도 않다. 서로 다른 동작을
오래 섞으면 회전/리듬/지지 충돌이 늘 수 있다. 공식 안내대로 다음 행동의 초반에 전이가 발생하므로
그 행동을 실현할 시간까지 확보한다. 하나의 걷기를 문장마다 끊지 않는다.
후보를 K=5/10/20 등으로 비교할 수 있으나 이는 탐색 예시이지 최적값/보편 허용 범위가 아니다.
K는 앞 구간의 실제 길이보다 작게 잡고 전체 모델 입력 길이도 확인한다.

## continuation / in-between / 부분 교체

### 이미 만든 모션 뒤 이어가기

1. A의 끝 한 장면뿐 아니라 짧은 실제 이력을 뽑는다. 진행 속도, angular velocity,
   support phase, 소품 지지 상태를 함께 기록한다.
2. 이 이력을 Kimodo skeleton/미터/Y-up/canonical root 좌표로 옮기고 새 생성의 앞 구간에
   FullBody + 필요한 손/발 방향 조건으로 둔다. 지나치게 많은 dense body 조건은 피한다.
3. 새 prompt에도 지속 상태를 명시한다. 예: 걷다가 손을 흔드는 사람은 몸이 계속 걷는다는
   문맥을 유지한다. `stands, begins`를 무의식적으로 새로 넣지 않는다.
4. 결과를 원래 월드로 되돌리고 overlap을 한 번만 남긴다. 기존 확정 prefix는 보존한다.
   이력 조건은 속도를 전달하는 근거이지 독립적인 velocity API/동일 프레임 보존 보장이 아니다.

### A와 B 사이 연결

양쪽을 동일 좌표/축/단위로 정렬하고, A tail과 B head의 자세·진행·접촉을 조건으로
짧은 bridge를 생성한다. 한 점씩만 맞춰도 위치는 이어질 수 있지만 속도는 끊길 수 있다.
양쪽 짧은 이력을 쓰되 이동 불가능한 시간, 반대 지지 발, 양손 위치 충돌은 목표부터 수정한다.
경계에 억지 blend를 오래 걸어 균형을 숨기지 않는다. B의 실제 지지 상태가 달라지면
추가 스텝/체중 이동을 포함하는 전이를 만든다.

### 일부만 바꾸기/루프

전체 재생성이 아니라 바꿀 구간의 양 경계를 조건으로 새 후보를 만든 후 해당 구간만 교체한다.
공개 high-level API에 이름 있는 부분편집 버튼/보존 마스크가 있다고 가정하지 않는다.
루프도 자동 보장이 아니다. 시작·끝 지지 위상/속도를 맞추고 root 누적 이동과 회전수를 보존한다.
360도 회전의 양 끝 quaternion이 같다는 이유로 회전을 없애지 않는다.

## Blender와의 연결 계약

몸의 기반 동작을 retarget한 뒤 목표 리그에서 접촉을 마무리한다. 손목 도달만 Kimodo로 맞추고
손가락 그립은 Blender에서 다룰 수 있다. 팔 일부를 수정해도 견갑·몸통·골반 보상이 필요할 수 있다.
소품 지지는 선반→손→다른 손/그릇과 같이 시간별로 기록하고, grasp/release 프레임을 전이에 포함한다.
무대의 계단/접시 테두리는 실제 높이와 landing/contact 구간을 사용한다.
상반신 레이어 + 하반신 보행도 둘이 독립이라는 뜻은 아니므로 중심 이동/팔 충돌을 다시 확인한다.

## 다음 제작에서의 최소 비교 실험

연구만 요청된 턴에는 이 실험을 완료했다고 하지 않는다. 제작/수정이 요청되면 비용·길이를 좁혀 실행한다.

- 동일 모델/텍스트 인코더/FPS/seed 집합으로 continuous walk와 walk→turn→wave를 분리 시험.
- 단일 prompt / multi-prompt / 앞뒤 이력 bridge를 비교. seed 고정만으로 서로 다른 길이의
  샘플이 동일해지는 것은 아니므로 통제 비교이지 완벽한 paired noise 비교는 아니다.
- 먼저 경로의 속도 프로파일을 검사하고, 원본→공식 후처리→우리 수정→retarget별 파일을 보존.
- seam 주변 root/관절 속도·가속도·방향·지지 발 드리프트와 표면 틈/침투를 측정한다.
  root가 느리다는 것만으로 춤/인사를 정지 오류로 판정하지 않는다. root-relative 관절 운동도 본다.
- actual segment frame count와 output shape가 맞아야 seam 통계를 계산한다. skeleton별 foot mapping 사용.
- 실제 정상속도 재생 + 경계/접촉 확대를 함께 평가. 지표 하나, 평균 신장, exit 0만으로 승인하지 않는다.
- 승인이 난 짧은 행동/전이 조합만 긴 영화로 확장한다. 기존 완료 영상/실패 후보는 덮어쓰지 않는다.
