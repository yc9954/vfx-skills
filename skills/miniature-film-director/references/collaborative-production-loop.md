# 사용자 방식에 맞춘 제작 루프

먼저 최신 사용자 지시와 기존 `film_state.json`에서 제작 단위, 자산, 모델, 시점과 다음
산출물을 복원한다. 아래는 이 테이블 시리즈의 현재 이미지 중심 경로다. 다른 요청에는
그 요청의 순서를 적용한다. 상태 확인·조사·지침 수정만 하는 턴을 제작으로 확대하지 않는다.

## 잘 나왔던 경로를 다시 실행할 때

사용자가 좋아한 실제 결과와 그 결과의 저장된 요청을 먼저 연결한다. 실행 파라미터,
프롬프트 원문, 참조 순서·역할과 필요한 중간 이미지를 복원한다. 배경색만 바꾸라는 요청에는
제작 배경의 색 표현과 새로 생성한 참조 ID만 바꾼다. 초록 의상까지 일괄 치환하지 않는다.
문장 순서·카메라·캐릭터 크기·자리·소품·동작 조건을 더 좋은 표현이라는 이유로 다시 쓰지 않는다.
제출 전 원문과 차이를 확인해 현재 허용한 변경만 있는지 기록한다.

이 시리즈의 성공했던 기준에는 Cook의 실제 키=접시 지름의 0.30배, Junior=Cook의
0.60배(접시 지름의 0.18배)가 있었다. 이것은 원문에서 유지할 크기 지시이며 생성 결과의
측정값으로 인증하지 않는다. 실제 결과는 사용자가 좋아한 이미지와 접시 지름을 기준으로
비교한다. 탑뷰를 보강한다며 이 크기 지시를 빼거나 전신을 크게 재배치하지 않는다.
성공한 이미지 요청이 접시 고정용 첫 참조와 출연자·소품 외형용 두 번째 참조를 사용했다면
같은 순서와 역할을 재현한다. 두 번째 참조의 낮은 시점·큰 인물·이동한 접시는 계승하지 않는다.
새 시점 예문은 신규 요청의 골격이며, 사용자가 유지하라고 한 성공 프롬프트를 대체하지 않는다.

## 기본 경로: 한 접시 이미지 → 장면 → 접시별 배경 제거 → 네 방향 배치 → 배경 합성

1. **접시 원본**: Higgsfield의 Nano Banana로 접시만 있는 초록 배경의 16:9 이미지를
   먼저 만든다. 바닥 평면 기준 고도각 75도로 내려다본다. 접시 형태·재질·중심·크기·방향과
   주변 작업 공간을 이 이미지에서 정한다. 과거 검은 배경·다른 각도·네 접시 동시 제작을
   현재 기본값으로 가져오지 않는다. 최신 사용자 선택에 따라 이 시리즈는 초록색을
   접시 원본·엔티티 이미지·한 접시 영상의 제작 배경에 사용한다. 분리 이후에는 투명 전경을 배치한다. 배경은 미술 요소가
   아닌 제작용 단색이며 그라데이션·무늬·의상에 번지는 초록 조명을 요구하지 않는다.
   다른 프로젝트나 명시적으로 다른 색을 고른 사용자에게 이 색을 강요하지 않는다.
   사용자가 배경색을 바꿔 처음부터 다시 만들라고 하면 접시→엔티티 이미지→영상의
   생성 프롬프트부터 새 색으로 바꿔 재제작한다. 기존 영상의 키잉·색 변환본을
   새 색에서 생성한 소스라고 대신 넣지 않는다. 기존 캐릭터 엔티티의 정체성은 재사용한다.
   기존에 잘 나온 초록 소스로 초안을 요청하면 그 이미지·영상을 그대로 재사용한다.
   프롬프트·시점·캐릭터 크기를 다시 설계하거나 새 생성·색 변환을 끼워 넣지 않는다.
2. **엔티티 배치**: 접시 원본을 참조하고 기존 Higgsfield `@` 캐릭터 엔티티를 주변에
   배치해 한 장의 기준 이미지를 만든다. Nano Banana와 기존 엔티티를 재사용하며 접시의
   위치·크기·방향을 유지한다. 캐릭터 재생성·재등록이나 새 3D 리그를 선행 단계로 넣지 않는다.
   접시 원본의 카메라까지 유지한다. 엔티티 참조의 얼굴·의상·머리 정체성만 이어받고
   정면/측면 포트레이트 시점을 복사하지 않는다. 머리·어깨 윗면, 몸의 단축과 위에서 본
   도구 경로를 프롬프트에 명시한다. 생성 후 [탑뷰 검사](../../visual-image/references/projection-look-gate.md#near-top-down-camera-check)를
   통과한 실제 이미지만 다음 영상 입력으로 쓴다. 잘못된 시점의 이미지를 작업용이라는 이유로 넘기지 않는다.
3. **행동 지시**: 기준 이미지에서 출연자, 소품 출처, 준비→행동→반응→끝 상태, 길이와
   소리를 구체화한다. 필요한 콘티·시작/끝 이미지만 더한다. 짧은 행동에는 간결한 지시로
   충분하며 모든 장면에 별도의 전체 콘티나 프리비즈를 요구하지 않는다.
4. **한 접시 영상**: 기준 이미지를 시작 이미지로 사용해 Kling 3.0에 동작을 부여한다.
   16:9·75도 시점·초록 배경과 고정 접시를 유지하도록 지시하고 실제 결과에서 확인한다.
   일반 이미지→영상과 Motion Control의 입력 역할을 구분해 현재 도구에서 지원하는
   모델·길이·입력만 사용한다. 기본 경로에 모션 참조 영상을 자동 추가하지 않는다.
5. **접시별 배경 제거·경계 보정**: 각 한 접시 영상에서 접시·캐릭터·소품을 함께 분리한다.
   [접시별 분리·합성 지침](per-plate-compositing.md)에 따라 원본 RGB와 동기화된 알파/마스크를
   보존하고 실제 제거 결과를 확인한다. 초록색 옷, 머리, 손, 도구와 액체가 지워진 결과를
   네 번 복제하지 않는다. 고정 접시와 움직이는 인물의 경계를 구분해 필요한 곳만 보정한다.
   한 소스 반복 사용이면 한 번 검수한 분리본을 재사용하며, 서로 다른 영상이면 각각 분리한다.
6. **네 좌석 배치**: 검수한 투명 전경을 좌석별 방향에 맞게 회전·크기 조정·배치한다.
   회전을 미러링으로 대체하지 않는다. 네 좌석이 반드시 네 개의 서로 다른 각도를 뜻하지
   않으므로 기존 좌석 배치를 따른다. 서로 마주 보는 두 쌍이면 위쪽 둘 180도·아래쪽 둘 0도다.
   한 접시의 16:9 소스와 실제 투사 캔버스의 비율·좌표는 별도로 유지한다.
   기존 소스와 과거 파란 시도·색 변환본·요청·영수증은 보존한다.
   [compose_seat_tiles.py](../scripts/compose_seat_tiles.py)는 명시적 단색 초안의 빈 타일 외곽만
   정리하는 도구이며 전경 분리나 임의 배경 합성용이 아니다.
7. **전체 배경 합성**: 사용자가 제공/선택한 배경 위에 네 좌석 전경을 로컬 합성한다.
   배경은 접시 아래까지 이어지고 사각 제작 배경은 남기지 않는다. 배경의 화면비 처리는
   패턴·중앙 문양과 현재 투사 캔버스를 보고 정하고 기록한다. 전경을 포함한 합성본을
   생성형 편집 모델에 다시 넣는 단계는 기본값이 아니다. 요청받은 생성형 배경 편집에는
   현재 지원 입력·권한을 확인하고 실제 후보의 전경 보존을 별도로 비교한다.
8. **검수·납품**: 실제 출력의 이야기·연기·접촉·미술·오디오와 파일 규격을 구분해 확인한다.
   실패한 부분의 이미지·동작 지시·합성만 수정하고 영향받는 결과를 다시 본다.
   기획 변경은 사용자와 논의하며, 프리비즈 제작으로 자동 되돌아가지 않는다.

## 프리비즈는 문제에 맞춰 선택

프리비즈를 만들지 않고 위 이미지 경로로 시작할 수 있다. 사용자 요청이 있거나 해결되지
않은 이동 경로·가림·접촉 순서·타이밍을 확인할 때만 검토한다. 무엇을 확인할지 먼저
한 문장으로 정하고, 이미지·행동 비트·로컬 합성으로 충분한지 판단한다.

3D 검사가 필요할 때 Blender로 해당 구간의 최소 가이드를 만든다. 기존 유효한 가이드는
재사용한다. 사용자가 전체 메시 프리비즈를 요청한 경우에만 그 전체 범위를 만들고
[대조 지침](../../animation-causal-staging/references/storyboard-previs.md)을 따른다.
프리비즈를 선택한 것과 모델에 영상을 입력하는 것은 별도 결정이다. 한 인물의 동작 복사가
필요하면 Motion Control을 검토하되 지원 입력·가이드의 읽힘과 실제 후보를 확인한다.
프리비즈나 모션 참조가 여러 배우·소품·음식의 관계를 그대로 보존한다고 가정하지 않는다.

## 협의와 실행 권한

결과를 바꿀 미결정만 묻고 이미 정한 제작 방식을 다시 선택하게 하지 않는다. 사용자가
창작 컨펌을 요청한 경우 실제 기준 이미지·행동·필요한 콘티의 버전과 남은 가정을 보여준다.
선택한 가이드가 있으면 함께 제시한다. 승인 대상에 없는 프리비즈를 추가 관문으로 만들거나
이미 허가된 범위의 진행을 반복 확인하지 않는다.

창작 컨펌과 지출 권한은 별개다. 실제 입력·계정·견적·시도 범위에 맞는 현재 사용자 권한을
확인하고 기존 실행기·장부로 제출·회수·비용을 연결한다. 실패했다고 자동 재결제하지 않으며,
제출 여부가 불명확하면 기존 작업·청구부터 확인한다. 기술 완료는 품질 승인이 아니다.

## 기존 기록에 남기는 상태

기존 `film_state.json`의 `artifacts`, `decisions`, `checks`, `changes`, `runs`, `next_action`을
재사용한다. 선택한 제작 방식과 바로 다음 산출물을 최신 방향으로 기록하되 이전 자산·
해시·승인·실패 근거는 보존한다. 상위 `stage` 규약을 유지하고 필요한 경우 기존
`collaboration_phase`에 이미지 준비·행동 설계·생성·합성·후보 검수 등 실제 단계를 적는다.
`mesh_previs`는 그 작업을 선택했을 때만 사용한다. 이 기록은 자동 실행이나 유료 허가가 아니다.
