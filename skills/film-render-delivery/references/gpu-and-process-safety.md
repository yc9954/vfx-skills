# GPU, 시간, 프로세스, 저장 공간

## 실제 실행 환경에서 GPU 확인

- Blender 실행 파일/파이썬 환경, bpy 버전, 렌더 엔진과 장치를 탐색한다.
  다른 환경에서 GPU가 안 보였다는 기록을 현재 기계의 한계로 단정하지 않는다.
- Cycles라면 현재 버전의 장치 API로 Metal/CUDA/OptiX를 조회하고 선택된 장치,
  scene device, 실제 렌더 로그를 확인한다. 컴퓨터 사양만 보고 GPU 사용 중이라고 하지 않는다.
- CPU에 적합한 가벼운 변환/검사는 그대로 둔다. GPU 이동 비용보다 짧은 일을
  무조건 원격 GPU로 보내지 않는다. 원격 컴퓨트는 현재 요청의 허용 범위와 비용을 확인한다.

## 짧은 벤치마크

같은 장면·장치·해상도·샘플 수로 초기 준비와 정상 프레임 시간을 분리 측정한다.
동작/파티클 복잡도가 달라지는 대표 구간도 소수 시험한다.
`남은 프레임 × 최근 프레임 시간 + 아직 필요한 준비/인코딩`으로 범위 ETA를 제시한다.
관측되지 않은 GPU 배속이나 “몇 분”을 약속하지 않는다.
기본 100프레임 테스트 지시와 별도 1분 전체 제작 지시는 구분한다.

## 한 출력의 작성자는 하나

- 시작 전에 실행 중인 해당 렌더와 encoder, 출력 소유권을 확인한다. PID뿐 아니라
  명령·시작 시각·입력 장면·출력 경로로 같은 작업인지 확인한다.
- 매 실행은 고유 run ID와 출력 경로를 사용한다. 이미 파일이 있으면 기본적으로 거부한다.
  ffmpeg `-y`를 공유 출력 경로에 무조건 적용하지 않는다.
- 중단 요청의 반환은 종료 확인이 아니다. Blender가 신호를 다음 프레임까지 미루거나
  무시할 수 있다. 요청 범위의 정확한 렌더/자식 encoder만 정상 종료시키고 살아 있는지 재확인한다.
- 이전 부모가 끝나도 encoder가 파일을 잡고 있으면 새 작성자를 시작하지 않는다.
  다른 작업에 광범위한 `pkill`을 사용하지 않는다.
- 프레임 시퀀스를 재개할 때 장면 해시, 설정, 프레임 번호/누락/파일 유효성을 확인한다.
  다른 버전의 프레임을 섞지 않는다. 중간 MP4에 임의로 이어 쓰지 않는다.

## 입력을 고정하고 작업을 나누기

- 저장 장면, 연결된 텍스처/캐시, 설정의 버전을 먼저 고정한다. 실행 중 원본을 편집해야
  하면 별도 후보를 만든다. 외부 파일도 바뀔 수 있으므로 `.blend` 해시 하나만으로
  의존성이 고정됐다고 단정하지 않는다. 검사 후 최신 해시로 보고서 대상을 갈아끼우지 않는다.
- 긴 기하 검사와 렌더 비용을 분리 측정한다. GPU 렌더가 빨라도 CPU의 메시 평가/BVH
  생성/교차 검사가 병목일 수 있다. 대표 완결 행동에서 실제 비용과 결과를 확인한다.
  샘플 수를 줄이면 검사 범위도 함께 줄었다고 기록한다.
- 구간별 프레임/캐시는 임시 경로에 완성·검사한 뒤 원자적으로 확정한다. 재개 manifest에
  입력 버전, 설정, 프레임 범위와 각 파일 유효성을 연결한다. 아직 기록 중인 이미지나
  이전 후보 프레임을 완료 캐시로 재사용하지 않는다. 의도한 warm-up은 유지한다.
- 모션 리뷰 영상, 접촉 감사, beauty 전체 렌더를 별도 산출물로 추적한다. 모션 영상이
  끝났다고 beauty 렌더를 완료로 바꾸지 않고, 전체 영상이 실제 완료됐는데 예전 작업 메모의
  `underway`만 인용해 계속 실행 중이라고 말하지 않는다.

상태 페이지가 있으면 마지막 확인 시각, 실행 ID, 완료/실패/남은 범위와 결과 링크를 실제
프로세스·파일과 맞춘다. 페이지가 열리는 것과 상태가 최신인 것은 별개다. 도구 timeout이나
중단된 에이전트 턴은 렌더 종료의 증거가 아니다. 재개 전 정확한 작성자를 재확인한다.

## 디스크와 로그

- 사용 가능 공간과 예상 프레임/캐시 크기를 확인한다. 복구 가능한 프레임 캐시가 필요한지,
  한 임시 이미지/파이프 인코딩이면 충분한지 선택한다. 파이프 방식은 중간 재개가 어려움을 알린다.
- 로그는 해당 실행의 scratch 위치에서 크기를 제한한다. 렌더러 출력은 회전/제한된 로그나
  오류 시 tail로 관리하고 코드 폴더에 무제한 로그를 쌓지 않는다.
- 장면 반복 루프에 최대 횟수/진전 확인을 넣는다. 과거 modifier identity 루프가 거대 로그를
  만든 사례는 경고이지 모든 로그를 자동 삭제할 권한이 아니다.
- 임시 파일만 명확한 소유권 하에 정리한다. 기존 영상, 모델 가중치, 원본 `.blend`, 사용자 로그는
  요청된 정확한 대상이 아니면 지우지 않는다. 삭제하면 대상과 복구 가능성을 알린다.

## 증거를 같은 버전에 묶기

scene hash, source versions, settings, output hash, command, selected device,
실제 elapsed/frame count, 검사 구간/제외 범위를 기록한다. 토큰이나 인증 명령은 기록하지 않는다.
종료 뒤 영상 디코딩 검증과 원본 의존성 검사를 수행한다. 기술적 완료는 시각적 승인과 분리한다.
